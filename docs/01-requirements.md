# 需求文档

## 用户与目标

帮助运营人员在预算与截止时间内完成一份内容活动方案。Agent 需根据工具返回的实际结果动态调整计划，而非按固定流程执行。

## 输入

- 主题（topic）：内容活动的主题关键词
- 预算（budget）：以模拟单位计，上限约束
- 截止时间（deadline）：硬性时间约束

## 可用工具

| 工具 | 功能 | 关键参数 |
|---|---|---|
| search_material | 按主题检索合成素材 | topic |
| generate_script | 基于素材生成脚本草案 | material_id, plan_name |
| estimate_cost | 估算方案成本，返回是否超预算 | plan_name, budget |
| save_plan | 保存方案草稿（幂等） | idempotency_key, plan_name, script |

## 交付结果

- 任务计划：执行过的工具步骤列表
- 步骤状态：每步的工具名、成功/失败、返回摘要
- 工具结果：所有工具调用的详细返回
- 费用合计：最终方案的估算成本
- 已保存方案或未完成原因

## 范围

- 核心链路：ReAct 决策循环（决策 → 执行 → 观察 → 再决策）
- 运行方式：CLI
- 模型：离线 Mock 验证流程 + 真实 LLM 可切换接口
- 非范围：UI 界面、线上部署、多 Agent、生产级 Runtime

## 成功标准

1. 正常完成：输入完整时，Agent 完成素材检索、脚本生成、成本估算、方案保存全流程
2. 缺预算或截止时间：返回 incomplete 并说明缺失信息
3. 工具失败：失败步骤记为失败，不混入成功；Agent 尝试替代方案续跑
4. 预算超限：观察到超预算后自主改选替代方案重新估算
5. 重复执行：同一请求多次执行只产生一份草稿（幂等）
6. 步数/工具调用上限：超限时返回明确的 incomplete 状态
